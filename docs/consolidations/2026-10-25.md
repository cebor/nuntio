## Target picture

**nuntio core (app, window, tabs, panes).** `Core` dispatches; each feature with its own lifecycle owns one state struct in its own child module of `app.rs` (`MuxState` in `app_mux.rs`, `UpdateState` in `app_update.rs`), and `reload_config` calls one sync function per feature instead of inlining its rules. How the process ends is one value (`Exit`), not a set of flags.

**nuntio UI and input.** Overlays share `UiMetrics`, `style::Palette`, the named colors and primitives in `style.rs` (`rect`, `outline`, `corner_box`). The key name tables (config key, winit key, physical key) exist once. Menus build their rows through `Row` constructors.

**Services and platform glue.** A WSL distribution and its user are one `wsl::Distro`, which also builds every `wsl.exe -d … [-u …]` command. Windows constants come from `windows-sys`. User directories (config, cache, data) and the config read/write contract live in `nuntio-config`. Periodic background work runs on one `Ticker`. The updater shares its HTTP agent setup, and its staging paths clean up through a guard.

**Multiplexers.** `mux/` owns everything herdr and tmux: settings via `Tool::config`, command lines in `mux/launch.rs`, the session key of a pane via `MuxPane::agent_key`, the pure agent diff in `mux/herdr.rs`, and the inherited environment names. Socket answers are parsed, never substring-matched.

**nuntio-term.** One owner per grid predicate (`is_spacer`, `contains`), one WSL share parser (`wsl_share`), and shared unit-test fixtures (`test_support`).

**nuntio-render.** `Renderer` keeps shrinking into owners: `ImageCache` owns the image atlas and its regions; `Instance` constructors own the per-kind `uv`/`color` contract; text sizes and face styles define the cluster cache shape. Only re-exported items are public.

**nuntio-config and nuntio-config-tui.** `nuntio-config` judges a keybinding once (`Keybinding::check`), names theme formats once, owns the home-relative path rule, and offers `read_config_source`/`set_in_file` so no app writes a config nuntio would reject. The editor parses each edit once.

**Terminal apps and nuntio-tui.** `nuntio-tui` is the toolkit of every pane app: terminal lifecycle (`terminal::run`), popups, panels, headings, centered text, key hints, the prompt line with scrolling input, and list navigation. The notes app keeps its logic behind `Store`, its geometry in `notes/areas.rs`, and drawing in `ui.rs`.

**Tooling and documentation.** `cargo deny check` checks the same graph with or without `--all-features`. The docs name every child module and service thread, and the architecture diagram shows the multiplexer services and the updater's downloads.

- #71 `ci.yml` and `release.yml`: composite actions `.github/actions/linux-deps` (the apt line appears five times) and `.github/actions/appimagetool` (version, checksum and download in both workflows). Half of the change would land in `release.yml`, which only a tag push exercises.
- #72: one reader for the workspace `version` and `rust-version` (xtask `version()`, plus a `sed` in each of `ci.yml` and `release.yml`). For example, `cargo xtask workspace-info version|rust-version` would work, but it adds an xtask command and compiles xtask in jobs that only run `sed` today. This needs `release.yml` and is a user decision.

## Greenfield observations

- `Renderer`: after `ImageCache`, the glyph side is the next owner. `glyphs.rs` would hold the sprite maps, the cluster slots, the mask and color atlases and the atlas-full policy (`or_blank`).
- `app.rs`: `app_mux.rs` and `app_update.rs` now set the pattern of a child module with one state struct. Theme following and the clipboard could take the same shape once they hold more state.
- The notes `App` in `state.rs` (≈1,900 lines) can now split along `areas.rs`, list and todo navigation (`nuntio_tui::list`) and editing, when a second pane app shares the crate.
- `RemoteForeground` in `pane.rs` is Windows-only data with an `allow(dead_code)` elsewhere. A cfg'd `remote_foreground` accessor would remove it.

- **#55:** notes popups now share the settings editor's centering, which rounds a half cell up. With an odd leftover space they sit one row or column lower or further right than before.
- **UI states no screenshot showed:** warning and info banners (#32), the update and agents menus (#30), tab-bar overflow with scroll arrows (#31), the transparent-window corner cutout (#34), combining marks in UI text (#36), the notes failure screen and its conflict and quit-unsaved popups (#55), list scrolling past one screen, and mouse divider drags (#58, #61).

- **New dev-dependency:** `nuntio` and `nuntio-apps` now have a dev-dependency on `nuntio-config` with the `testutil` feature.
